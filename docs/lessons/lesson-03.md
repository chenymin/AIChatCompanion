# 第 3 课：把多轮上下文变成可观察的状态

目标：独立解释历史在哪里保存、何时进入请求、失败时怎样处理本轮状态。预计 3～4 小时。

起点：`lesson-02`；参考完成版：`lesson-03`。本课多轮、重置、历史与故障案例均**未执行，待用户验证**。

## 本课相对上一课新增什么

第 2 课完成一次请求后退出。本课保留单次模式，并增加交互式多轮入口与内存会话：

```text
cli 无位置参数
  → repl：逐行接收输入或命令
  → conversation：准备当前输入和有限历史
  → agent / ModelClient：生成回复
  → 成功：把本轮 user 与 assistant 一起提交到内存历史
  → 失败：报告错误，本轮不提交，已有历史仍保留
```

`/history` 查看内存历史，`/reset` 重置它，`/exit` 退出。这些是客户端程序处理的命令，不是模型理解后执行的工具。

Ctrl+C 会取消在途生成并退出；EOF 仅关闭输入，有在途请求时等待其完成或超时。`/exit` 与其他输入同样排队处理，不会越过尚未完成的轮次。

本课没有数据库、登录或用户隔离。进程退出后历史不保留；`/reset` 的范围是当前内存会话，不涉及原项目数据。

## 手动实验一：两轮输入

启动模拟交互模式，不传位置参数：

```sh
MODEL_MODE=mock npm run chat
```

依次输入：

```text
突然降温
我今天想学习 Agent
/history
/exit
```

预期：两轮正常回复后，历史中包含两条 user 与两条 assistant 消息。模拟回复含 `【模拟回复·第 N 轮】` 标记；轮次来自模拟器对本次请求中用户消息数量的计算，不代表真实模型拥有隐藏的持久记忆。

在模型调用前检查 messages：第二轮为什么能看到前一轮？是哪段代码把这些消息交给模型？这比仅看它回复“我记得”更能证明上下文来源。

原有单次命令仍有效：

```sh
MODEL_MODE=mock npm run chat -- '突然降温'
```

## 手动实验二：历史与重置

在同一交互会话中输入：

```text
我喜欢简短的回答
/history
/reset
/history
现在还有之前的记录吗
/exit
```

预期：第一次查看有本轮消息；reset 后再查看，内存历史为空。下一次生成使用重新开始的会话，mock 的轮次也从该请求的用户消息数重新计算。

不要用回复语气判断 reset 是否成功。应直接观察 `/history` 与断点中的 messages。

## 历史窗口的边界

内存历史有最多 20 条已完成角色消息的窗口（10 轮）；一条 user 或 assistant 都分别计数。`commitTurn` 追加一对消息后截取最后 20 条，`prepareTurn` 复制历史并追加当前 user，Agent 再在前面添加 system。因此模型请求最多 22 条消息，当前 user 和 system 不占那 20 个历史名额。

较早消息会移出窗口，所以 mock 的轮次标记不代表整个进程累计轮数：10 轮历史之后，本次可见 user 数最多为 11，标记也封顶第 11 轮。`/history` 只显示已提交窗口，不包含 system。没有摘要、数据库或隐藏记忆。

用断点区分三种数据：已经提交的历史、本轮准备发送的消息、成功后形成的新历史。查看具体实现时，核对窗口截取是在准备请求、提交历史还是两个位置，并说明当前用户消息与 system 指令是否属于同一计数范围。

本课 trace 中 `memoryCommitted: true` 表示已成功提交内存；`saved: false` 表示没有持久化。失败为 `memoryCommitted: false`，不要把内存提交和数据库保存混为一谈。

## 故障实验：生成失败时是否留下半轮历史

先写预期，再启动：

```sh
MODEL_MODE=mock MOCK_FAULT=error npm run chat
```

输入一条普通文本，再输入 `/history`，最后 `/exit`。

预期：生成报错后，REPL 仍可以处理后续命令；本轮失败输入和不存在的助手回复都没有提交到历史。断点检查 `src/conversation.ts` 的提交位置，确认它在生成成功后。

去掉故障开关重新启动后，默认路径应恢复。故障开关在启动时确定；不要求在同一进程里通过聊天文本修改环境变量。

这里的失败语义是课程刻意选择：成功才提交整轮。原项目采用不同保存时机，需要对照理解，不能把本课做法当成所有系统的统一要求。

## 与原项目对照

在原项目中搜索：

- `apps/web/app/(dashboard)/_components/inbox-chat.tsx`：`useChat`、`messages.slice(-20)`。
- `apps/api/src/routes/chat/inbox.route.ts`：`storedRecentMessages`、`promptHistory`、`insertAgentConversationMessage`、`saveAssistantTurn`。
- `apps/api/src/db/schema.ts`：`agentConversations`、`agentConversationMessages`。

两者都需要显式读取或保存上下文，但有三个区别：

1. 本课在一个本地进程内保存内存历史；原项目主要从数据库读取服务端会话历史。
2. 本课失败不提交本轮；原项目在正式生成前已保存用户消息，随后模型失败时可能留下单独 user 消息。
3. 本课只有一个当前内存会话；原项目还需要用户、Agent 与会话归属及隔离。
